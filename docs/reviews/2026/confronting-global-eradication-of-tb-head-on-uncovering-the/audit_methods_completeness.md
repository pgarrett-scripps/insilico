# Methods Completeness & Reagent Traceability Auditor

## Summary
This computational study of TB drug-resistant mutations employs bioinformatics analysis of literature-derived mutation data and molecular modeling. Detected categories include Computational/ML (primary), Chemicals/drugs (secondary), and Protocol provenance (cross-cutting). The manuscript describes a systematic pipeline with multiple bioinformatics tools but has significant gaps in reproducibility: critical software versions are missing or incomplete, random seeds are not stated, the dataset is not deposited in a public repository, and code availability is not addressed. Several delegated methods reference prior work without sufficient detail to verify protocol completeness. Data availability is not explicitly stated. These gaps are HARD blockers for independent reproduction of the computational analyses.

## HARD gaps — reproduction blockers
- **[Computational/ML/modeling] Dataset version, train/val/test split, and repository accession** — The study collected mutation data from 149 publications covering 31,073 Mtb isolates over 30 years (1988–2018). The manuscript states 'This atlas helps in better understanding mutation pattern across the globe' and describes creation of supplementary tables (S1, S3, S5–S11), but does not specify: (i) whether the compiled dataset is deposited in a public repository (GEO, Zenodo, Figshare, or similar); (ii) the exact version/date of the dataset; (iii) any train/validation/test split (if applicable to the ranking model). The dataset is the foundation of the study but is not made publicly available or versioned.
- **[Computational/ML/modeling] Software and tool versions (MODELLER, GROMACS, ConSurf, SIFT, PROVEAN, PolyPhen-2, I-MUTANT 3.0, mCSM, AutoDock, Pfam, InterProScan, SMART, COACH-D, 3D LigandSite)** — The manuscript names ~15 bioinformatics tools but provides incomplete version information: MODELLER v9.23 (stated), GROMACS 4 with GROMACS96 43A1 force field (stated), but versions are missing or incomplete for: ConSurf (no version), SIFT (no version), PROVEAN (no version), PolyPhen-2 (no version), I-MUTANT 3.0 (version stated but no build/date), mCSM (no version), AutoDock 4.2 (version stated), Pfam (no version), InterProScan (no version), SMART (no version), COACH-D (no version), 3D LigandSite (no version), PROCHECK (no version), ERRAT (no version), RING (no version). Methods section states 'we used ConSurf for determining sequence conservation' and 'SIFT, PROVEAN and PolyPhen-2 computational tools were used' without specifying versions or access dates, making exact reproduction impossible.
- **[Computational/ML/modeling] Random seeds and seed-averaging statement** — The manuscript describes stochastic computational procedures: MODELLER generates 'ten structural models for each variant' and selects the best by DOPE score; GROMACS performs energy minimization; AutoDock uses 'Lamarckian genetic algorithms implemented with 200 docking population size and 2 million energy evaluations.' No random seed is stated for any of these procedures, and no statement indicates whether results were averaged across multiple runs or seed-fixed for reproducibility. This is essential for deterministic replication.
- **[Computational/ML/modeling] Code availability statement** — The manuscript does not state whether custom code (for data curation, mutation ranking, consensus prediction, or analysis scripts) is available. No GitHub repository, supplementary code file, or code-availability statement is provided. The Methods section describes a complex pipeline but provides no link to executable code or pseudocode sufficient for independent implementation.
- **[Chemicals/drugs/dosing] Dose/concentration per experiment and vehicle** — This is a computational docking study, not a wet-lab experiment with administered doses. However, the manuscript does not state the ligand concentrations used in AutoDock docking simulations (e.g., molar concentration, number of ligand molecules in the docking box). The docking procedure is described as rigid-protein, flexible-ligand, but no ligand preparation details (protonation state, charge, conformer generation) are provided. This is a gap for computational reproducibility.
- **[Protocol provenance] Mutation ranking consensus procedure – protocol resolvability** — The manuscript describes ranking mutations into lethal/moderate/mild/neutral categories (Section 3.6.2.5) based on 'concordance analysis' integrating results from SIFT, PROVEAN, PolyPhen-2, I-MUTANT 3.0, mCSM, and AutoDock. However, no reference is provided for the concordance method, and the decision rule is not algorithmically specified. The text states 'a concordance analysis was done for integrating results from the previous mutation analysis for a proper validation and categorisation of mutations' but does not cite a method or provide pseudocode. This is a load-bearing analysis central to the paper's conclusions and cannot be independently reproduced.
- **[Protocol provenance] Data availability statement** — The manuscript does not include a data-availability statement. It is not stated whether the compiled mutation dataset (Supplementary Tables S1, S3, S5–S11) will be deposited in a public repository (e.g., Zenodo, Figshare, GitHub, or a TB-specific database). The statement 'was not certified by peer review' and copyright notice appear, but no open-data commitment is made. This is a HARD gap for reproducibility and open science.

## Unverifiable (raise as questions)
- **[Computational/ML/modeling] Hyperparameters and key parameters for bioinformatics tools** — While some parameters are stated (e.g., AutoDock grid 100×100×100 points with 0.375 Å spacing, GROMACS force field GROMACS96 43A1), many tools are invoked with default or unstated parameters: ConSurf conservation scoring (scale 1–9 stated in Methods but no threshold for 'highly conserved' vs 'variable' is given in the categorization); SIFT tolerance index threshold (≥0.05 'tolerant' vs ≤0.05 'deleterious' stated, but no mention of how borderline cases were handled); PolyPhen-2 (no PSIC score threshold stated); I-MUTANT 3.0 and mCSM (no stability change threshold stated for 'destabilizing' vs 'stabilizing' classification); COACH-D and 3D LigandSite (no confidence/score threshold stated for ligand-binding site prediction). The ranking into lethal/moderate/mild/neutral categories (Table 2) depends on these thresholds but they are not fully specified.
- **[Computational/ML/modeling] Metric definitions and ranking consensus procedure** — The mutation ranking into lethal/moderate/mild/neutral categories (Section 3.6.2.5, Table 2) is described as based on 'concordance analysis' integrating results from multiple tools, but the exact decision rule is not stated. The text says 'Functionally deleterious mutations that compromise residue conservation with reduced structural stability and binding affinity were categorized 'lethal.' The ranking accordingly goes down to 'moderate' and 'mild' as the level of these decreases.' This is qualitative and not algorithmically specified. How many tools must agree? What weights are assigned to conservation, stability, and binding affinity? The procedure cannot be independently reproduced.
- **[Protocol provenance] MODELLER protein structure modeling – protocol resolvability** — The Methods state: 'Structural models of WT and mutant target proteins were generated using MODELLER v9.23 [51,52].' References [51] and [52] are Webb & Sali (2016) and Eswar et al. (2008), both standard MODELLER citations. The manuscript provides some details (template selection by sequence identity and query coverage, selection by molpdf/DOPE/GA341 scores, PROCHECK/ERRAT validation, >90% residues in favored region). However, the exact protocol for template selection (e.g., BLAST parameters, E-value threshold, coverage cutoff) and loop modeling (if any) are not stated. The cited references are resolvable, but whether they contain the exact protocol used is unverifiable from the manuscript alone.
- **[Protocol provenance] GROMACS energy minimization – protocol resolvability** — The Methods state: 'Energy minimization of protein models was performed by GROMACS package using the GROMACS96 43A1 force field.' Reference [55] is Hess et al. (2008), a standard GROMACS paper. However, the manuscript does not specify: (i) minimization algorithm (steepest descent, conjugate gradient); (ii) convergence criterion (energy tolerance, max steps); (iii) constraints (e.g., position restraints on backbone); (iv) integration parameters (time step, neighbor list cutoff). These are essential for reproducibility. The cited reference is resolvable but does not necessarily contain the exact protocol used.
- **[Protocol provenance] ConSurf sequence conservation analysis – protocol resolvability** — The Methods state: 'Evolutionary conserved amino acids in different mycobacterial strains were identified using ConSurf. It is a bioinformatics tool that performs multiple sequence alignments between input protein sequence and homologous sequences and constructs a phylogenetic tree to determine evolutionary relations between them [57].' Reference [57] is Ashkenazy et al. (2016), a resolvable ConSurf paper. However, the manuscript does not specify: (i) the homolog database searched (e.g., NCBI NR, UniRef); (ii) E-value threshold for homolog selection; (iii) alignment algorithm; (iv) phylogenetic tree method. The ConSurf web server has default parameters, but these are not stated. The cited reference is resolvable but the exact protocol is unverifiable from the manuscript.
- **[Protocol provenance] AutoDock molecular docking – protocol resolvability** — The Methods state: 'AutoDock 4.2 docking tool was used for determining binding orientation and binding affinity... Lamarckian genetic algorithms implemented with 200 docking population size and 2 million energy evaluations, were used for docking experiments [81,82].' References [81] and [82] are Morris et al. (1998, 2009), resolvable AutoDock papers. However, the manuscript does not specify: (i) number of docking runs; (ii) cluster analysis method and RMSD threshold; (iii) how the 'best conformer' was selected (lowest energy, highest cluster size, consensus); (iv) ligand preparation (protonation, charge calculation method); (v) grid center and spacing (stated as 100×100×100 with 0.375 Å, but no justification or ligand-specific centering described). These are critical for docking reproducibility. The cited references are resolvable but the exact protocol is unverifiable.

## SOFT gaps — recommended
- **[Computational/ML/modeling] Hardware and compute environment specification** — The manuscript does not specify the hardware used (CPU/GPU, RAM, compute cluster vs local machine) or provide an environment file (conda, Docker, requirements.txt). This is a SOFT gap but limits reproducibility of computational performance and potential numerical precision issues.

## Documented (for the record)
- **[Chemicals/drugs/dosing] Drug identity and source (INH, RIF, PZA, EMB)** — The four first-line TB drugs are named: Isoniazid (INH), Rifampicin (RIF), Pyrazinamide (PZA), and Ethambutol (EMB). In the Methods section under 'Drug binding affinity analysis,' it states: 'The ligands INH, PZA, EMB and RIF for catalase-peroxidase, pyrazinamidase, arabinosyl transferase and DNA-directed RNA polymerase subunit beta proteins were retrieved from PubChem database [80] in mol2 format.' This provides source (PubChem) but not specific catalog numbers or CAS numbers. However, these are well-known, off-the-shelf drugs, and retrieval from PubChem is a standard, traceable method.
- **[Protocol provenance] Data collection and literature search – inclusion/exclusion criteria resolvability** — The Methods section provides detailed inclusion/exclusion criteria: 'Publications were selected based on the following criteria: (i) published original data; (ii) analysis performed on strains of Mycobacterium tuberculosis obtained from a clinical sample; (iii) phenotypic drug susceptibility testing (DST) was done; (iv) characterizing mutations by sequencing (either DNA or pyrosequencing); (v) information available on individual amino acid mutations. Publications were excluded if (i) laboratory Mtb strains used; (ii) phenotypic DST not performed; (iii) sequencing not done for determining drug-resistant mutations; (iv) individual amino acid level mutation data not provided; (v) publication contained inconsistent mutation data.' These criteria are explicit and resolvable. Figure 4 shows the PRISMA-like flow diagram. However, the search strategy keywords are listed but no Boolean operators or database-specific syntax is provided, and no protocol registration (PROSPERO) is mentioned.
