# Reproducibility Reviewer

## Summary
The manuscript develops a theoretically sound stochastic SIR framework with regime switching and derives exact recursive formulas for joint distributional analysis. However, reproducibility is significantly compromised by the gating of code and processed data behind 'reasonable request', which violates current standards for load-bearing computational artifacts. The empirical application to Luxembourg mpox data is illustrative rather than inferential, and while the mathematical development is rigorous, the practical replicability of the numerical scenarios and figures depends entirely on author discretion. The manuscript would require either immediate deposit of code and data with a working DOI/accession, or a major revision to move from HARD to SOFT reproducibility status.

## Strengths
- Mathematical framework is fully specified: the generator matrix (Eq. 1), recursion formulas (Theorems 2–4), and boundary conditions are explicit and verifiable in principle.
- Proofs are provided in Appendix A, allowing independent verification of the theoretical claims without relying on author implementation.
- Numerical procedure is documented in detail: ODE integration method (fourth-order Runge–Kutta, 100 substeps per week), optimization algorithm (L-BFGS-B), box constraints, starting values, and Laplace-transform inversion method (Abate–Whitt with specified parameters: A ≈ 18.4, 15 initial terms, 11 Euler averaging terms) are all stated.
- Baseline calibration is transparent: fixed infectious period (γ = 1/3 per week), Poisson observation model, and parameter estimates with confidence intervals are reported.
- Scenario specifications are explicit: transmission coefficients (b₁ = 0.99, b₂ = 0.743, b₃ = 0.495), switching rates (λ = 0.35, 0.05), vaccination rate (ψ = 0.05), and state-dependent escalation function (Eq. 19) are all given numerically.
- Data source is public: mpox incidence from Our World in Data with a URL provided (https://ourworldindata.org/mpox).

## Weaknesses
- Code and processed data are gated behind 'reasonable request': The manuscript states 'The processed data and computer code used to reproduce the numerical results are available from the authors upon reasonable request.' This is a HARD flag for load-bearing artifacts. No repository link, DOI, or accession number is provided. An independent group cannot obtain these without author discretion, violating current reproducibility standards for computational work.
- No version control or commit hash: Even if code were deposited, no repository URL, commit hash, or version tag is given. The statement 'available from the authors upon reasonable request' provides no permanent, citable reference.
- No computational environment specification: Software versions (Python/R version, NumPy/SciPy versions, optimization library versions) are not stated. The Abate–Whitt inversion is described procedurally but no library or implementation reference is given (e.g., is this a custom implementation or a standard package?).
- Raw data processing steps not fully documented: The manuscript states weekly aggregation was performed ('aggregated into calendar weeks using Monday as the week start') but does not specify the exact code or intermediate outputs. The handling of partial weeks is mentioned but the precise aggregation rule is not given (e.g., how are partial-week counts handled in the Poisson likelihood?).
- No intermediate outputs or checksums: While three basic sanity checks are mentioned (Φ_{s,i,p}(0,1) = 1, sum of h^(n) = 1, sum of probabilities = 1), no intermediate numerical outputs, checksums, or example computations are provided to verify that an independent implementation produces the same values.
- Figures lack explicit traceability to code/data: It is not stated which script or function produces each figure (Figures 2–11). For example, is Figure 2 produced by a deterministic ODE solver, and which code block? Are Figures 3–11 produced by the recursive solver, and in what order?
- Numerical inversion grid and tolerance not fully specified: The Abate–Whitt inversion uses a finite grid with 120 points and upper endpoint set to max_j{E_j[T] + 4 SD_j(T)}, but the lower endpoint and spacing rule are not stated. Tolerance for 'non-finite or negative' values is described as 'set to zero before plotting', but no threshold is given.
- Rounding and integer conversion rule for initial conditions: The manuscript states 'Ŝ(0) was rounded to the nearest integer, while Î(0) was rounded subject to a lower bound of one infectious individual', but does not specify the exact rounding function (e.g., round-half-up, round-half-to-even). This affects reproducibility of the integer initial state (S(0) = 62, I(0) = 1).
- No seed or random-number handling: The optimization uses multiple random starting values ('Additional starting values were generated randomly within the admissible parameter bounds'), but no random seed is stated. This affects reproducibility of the calibration step.

## Questions
- Will the authors deposit code and processed data to a permanent, versioned repository (GitHub with a release tag, Zenodo, or similar) with a DOI before or at publication, rather than gating them behind 'reasonable request'?
- What software versions (Python/R, NumPy/SciPy, optimization library, Laplace-inversion library) were used? Was the Abate–Whitt inversion implemented custom or via a published package?
- Can the authors provide the exact aggregation rule for partial weeks in the Luxembourg data? Specifically, how are the first (16/06–22/06) and last (07/09–13/09) partial weeks counted in the Poisson likelihood?
- What is the random seed (or seed-averaging procedure) used for the random starting values in the L-BFGS-B optimization? This affects reproducibility of the baseline calibration.
- Can the authors provide intermediate numerical outputs (e.g., the computed values of Φ_{s,i,p}(z, u) for a small example state, or the extinction-time moments for Scenario 1) so that an independent implementation can be validated?
- For the Abate–Whitt inversion, what is the lower endpoint of the time grid, and what tolerance threshold is used to decide whether a value is 'non-finite or negative'?
- Which specific script or function produces each of Figures 2–11? Are there intermediate outputs (e.g., the PMF vectors or density arrays) that could be inspected?
- The manuscript states the fitted model 'should be interpreted as an effective baseline calibration' rather than a detailed reconstruction. Does this mean the one-phase model is intentionally misspecified to represent the observed data? If so, how does this affect the validity of using the fitted parameters (b̂ = 0.99) as the baseline for the switching scenarios?
