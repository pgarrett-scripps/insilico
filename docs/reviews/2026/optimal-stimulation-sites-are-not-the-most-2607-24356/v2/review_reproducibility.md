# Reproducibility Reviewer

## Summary
The manuscript's central, causal claims about stimulation efficacy rely on a complex computational pipeline. While the code is promised to be available, the current state of data and code availability, combined with insufficient detail on key procedural decisions, constitutes a HARD barrier to independent reproduction. The core analysis is built on a specific, balanced subset of the ADNI cohort, but the exact session IDs used for each subject and the random seeds for the reservoir and cross-validation folds are not provided, making exact replication impossible. The authors must deposit all load-bearing artifacts and specify all critical parameters to support their claims.

## Strengths
- The manuscript explicitly commits to open-sourcing all analysis and figure-generation code, which is a strong foundation for reproducibility.
- The methods section provides a clear, step-by-step description of the reservoir model, fitting procedure, and classification pipeline.
- The authors correctly identify and use a leave-one-patient-out cross-validation scheme for the final therapeutic target validation, a crucial guard against leakage.

## Weaknesses
- HARD: Load-bearing data subset is not uniquely identifiable. The manuscript states a 40-session CC subsample was used to balance the 40 AD subjects for core analyses (Figs 2-6). The exact session IDs (or ADNI subject/session identifiers) for this subsample are not provided. ADNI contains multiple sessions per subject; using different sessions would yield different reservoir fits and results. Without this list, an independent group cannot obtain the same inputs, breaking the reproduction chain. Remedy: Deposit a table listing the specific ADNI subject and session identifier (e.g., `sub-XXX_ses-YYY`) for each of the 40 CC and 40 AD sessions used in the main analyses.
- HARD: Critical random states are unspecified. The reproducibility of the entire pipeline hinges on several random components: the fixed random recurrent weights `J` and input weights `Jin` of the reservoir, the stratified splits for the 10-repeat 5-fold CV in Fig. 3, and the random forest seeds. The manuscript states the reservoir is "fixed random" and "reused for every session," but without a seed or the actual weight matrices, the exact dynamical system cannot be reinstantiated. Remedy: Provide the random seed(s) used to generate the reservoir matrices and the seeds/fold indices for all cross-validation procedures (e.g., via a saved `random_state` in scikit-learn). Ideally, the pre-initialized `J` and `Jin` matrices should be deposited.
- SOFT: Computational environment and hardware are not described. While the code is promised, the environment (Python version, library versions) and computational resources needed to run the analyses (e.g., memory, approximate runtime) are not mentioned. This creates friction for replication. Remedy: Include a `requirements.txt`, `environment.yml`, or a container specification, and note the approximate compute requirements.
- SOFT: Mapping from scripts to figures is implied but not explicit. The code repository will presumably contain scripts, but the manuscript does not specify which script generates each key figure (e.g., Fig. 3, Fig. 4, Fig. S5). Remedy: In the repository README or a companion document, explicitly map figure numbers to script names.
- HARD: Promise of future availability is not current availability. The Data and Code Availability section states "All analysis and figure-generation code is openly available at [GitHub URL]." At the time of review, this link must be live and contain the version of code used to produce the manuscript's results. A promise is not availability. Remedy: Ensure the repository is public and contains a commit/tag corresponding to the manuscript submission.
- The preprocessing step of regressing out "24 head-motion parameters" is mentioned but not detailed; a reference or explicit list is needed for exact replication (this is a borderline HARD/SOFT issue, leaning SOFT if a standard FSL/SPM pipeline is implied, but clarity is best).
- The parameter `f` (feedback gain) is given as 0.1, but its unit and the scaling of the input `u(t)` relative to the target `s_hat(t)` could affect dynamics; a brief justification or sensitivity note would aid reproduction.
- The statement "sessions were grouped by subject, and per-subject quantities used the first available session unless otherwise stated" is clear, but the exception "unless otherwise stated" is not elaborated upon for any analysis.

## Questions
- Please provide the exact list of ADNI subject and session identifiers for the 40 CC and 40 AD sessions used in the core reservoir fitting and stimulation analyses (Figs 2-6).
- Please provide the random seed(s) used to generate the reservoir's `J` and `Jin` matrices and the saved fold indices/seeds for the cross-validation in Fig. 3 and the leave-one-patient-out validation in Fig. S9.
- Can you confirm that the GitHub repository linked in the manuscript is currently public and contains a version-tagged commit of the code used to generate all reported results and figures?
