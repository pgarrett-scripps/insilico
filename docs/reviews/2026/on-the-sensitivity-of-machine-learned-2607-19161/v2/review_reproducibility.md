# Reproducibility Reviewer

## Summary
The manuscript provides a generally reproducible study. Core code and data sources are cited, and the experimental design is described with sufficient detail for a knowledgeable group to attempt replication. However, key load-bearing artifacts—specifically, the custom scoring rule implementations and the exact training configurations—are not directly accessible via a versioned repository or archive, creating a HARD barrier to full computational reproducibility. The procedural description is adequate, but the lack of a consolidated, accessible codebase is a significant omission.

## Strengths
- The study is built on publicly available foundational data (ERA5), and the training framework (Anemoi) is open-source, providing a solid starting point.
- The methodology section details the scoring rules, model architecture, and training schedule with specific hyperparameters (e.g., learning rates, rollout steps, embedding dimensions), which is commendable.
- The authors explicitly describe the use of `torch.compile` for efficiency, a practical detail that affects the feasibility of replication.

## Weaknesses
- Load-bearing claim: The comparative forecast skill results depend on the specific implementation of novel scoring rules. The manuscript introduces several custom scoring rules (graph energy score, graph variogram score, etc.) and a multi-scale loss formulation. The claim that "multivariate scores are a viable alternative to CRPS-based training" rests on the correctness and fidelity of these implementations. Without the code, an independent group cannot verify that the reported differences (e.g., graph energy score performing best in the tropics) are not artifacts of bugs, subtle implementation differences, or mis-specified graph connectivities. The alternative is that the observed performance differences stem from such implementation variances rather than the intrinsic properties of the scoring rules. Distinguishing this requires access to the exact code used to compute the losses during training.
- Load-bearing claim: The spectral analysis conclusions are contingent on the precise spectral transform and weighting procedures. The findings on how different losses shape forecast spectra are central to the paper's contribution. However, the spectral transform ("spherical harmonic transform capability recently added to Anemoi") and the ad-hoc weighting schemes for spectral bands and specific variables are described only in prose. The exact implementation of these transforms (e.g., truncation handling, normalization) and the precise numerical values of the weighting factors are not provided. An independent group could produce different spectral results using a different spectral library or slightly different weights, making the specific spectral comparisons non-reproducible. The claim that "scale awareness alone does not guarantee realistic variability" could be an artifact of the particular, undocumented weighting choices.
- HARD: The custom code for the scoring rules and the complete training pipeline is not available. The manuscript states the work uses the "Anemoi framework" and that "All scores are implemented in the Anemoi framework." While Anemoi is open-source, the specific implementations of the novel scoring rules (fGESgraph, fGVSgraph, etc.) and the multi-scale loss are not linked to a versioned repository, commit hash, or archived code supplement. A reader cannot obtain the exact code used to generate the results. This is a HARD reproducibility failure for these load-bearing components.
- SOFT: The computational environment and hardware specifications are omitted. While the model size is noted, details like PyTorch version, CUDA version, and the type of GPU/TPU used are missing. This affects the feasibility of replication, as performance and potential numerical differences can be hardware/software-dependent.
- SOFT: There is no mapping from specific results to specific code scripts. It is not clear which script or notebook was used to generate each figure (e.g., Figure 2 forecast skill plots, Figures 3-14 spectral plots). A replicator would need to reverse-engineer the pipeline from the methodology description.
- SOFT: Random seeds or a statement on seed averaging are not provided. The training of neural networks and the generation of ensemble members are stochastic processes. The lack of a reported seed or a statement that results are averaged over multiple seeds introduces unnecessary variance into the replication attempt.

## Questions
- Please provide a versioned repository (e.g., GitHub commit hash, Zenodo DOI) containing the exact code used to implement the novel scoring rules (graph energy, graph variogram, multi-scale loss, spectral losses) and the training/evaluation scripts that produced the figures in this manuscript.
- For the spectral loss experiments, please provide the exact numerical weighting factors applied per variable (e.g., geopotential, wind) and per spectral band (ℓ = 0–10, etc.), either in the manuscript or in the code repository.
- Please specify the software environment (e.g., PyTorch version, Anemoi commit) and the primary hardware used (e.g., GPU model type) to facilitate computational replication.
